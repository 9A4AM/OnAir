## 2026-10-18 FSQ and IFKP
Two separate new modes: FSQ (family 113, active 114, std 115; five speeds, directed messages with sender, addressee, command, CRC of the callsign) and IFKP (family 116, active 117, std 118; three speeds). One shared 33-tone receiver (core/src/fsq/kbd33.cpp: band search, tone grid, running sums of 73 positions, speed and timing from the sums, history decode on lock), a shared station and generator, two thin receivers, one UI template. Synthetic tests only; parameters and varicode from fldigi's sources, not checked against a real transmitter.

## 2026-10-19 Yaesu System Fusion receiver mode (WIP), voice via user-installed codec
Branch fusion-028 from 0.2.8. Family 128, engine standard 130, telemetry code 129 (the engine's activeStd is the standard minus one), "Yaesu Fusion (WIP)" in the amateur digital voice group with M17 and D-STAR. core/src/fusion: fusion_proto (sync D471C9634D, FICH with CRC-16 + 4 Golay words + rate-1/2 K=5 code + interleaver, DCH units with PN(9,5) whitening, VD2 voice majority code, frames of all four data types), fusion_gen (test signal + C4FM modulator), fusion_rx (M17-style front end, sync correlation, 100 ms frame tracking, callsigns CSD1-3, slow data text, polarity). Voice goes to the speech codec plug-in with id ysf (no codec in the tree); without it the panel says codec not installed. Written from Yaesu's public Amateur Radio Digital Specs 1.01. Not verified on air: no real capture. Noted while wiring: the DGPS and DME engine cases in 0.2.8 use `a == 122/123` while the engine activeStd is the standard minus one, and their UI checks use rx.standard == 120; test_dgps_mode and test_sitor_mode expect old kNumFamilies values.
